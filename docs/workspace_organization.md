# Workspace Organization

This repository now contains both core code and a growing amount of experiment,
evaluation, and paper-related material. To keep the workspace maintainable,
follow these boundaries.

## What should stay versioned

- `egoemg/`: source code, datasets wrappers, training/eval entrypoints.
- `config/`: Hydra configs that define reproducible experiments.
- `scripts/`: reusable utilities for conversion, evaluation, and visualization.
- `docs/`: protocols, design notes, and workflow references.
- `test_results/`: curated evaluation outputs only.
  - Keep `results.csv`, `README.md`, and small metadata files such as
    `overrides.yaml`.
  - Do not keep Hydra dumps, raw logs, or duplicated artifacts here.
- `assets/`: small static assets that are genuinely part of the repo.

## What should stay local only

- `logs/`, `local_artifacts/`, `tensorboard/`, `checkpoints/`: run artifacts.
- `.vscode/`, `.claude/`, `.codex`: personal editor and agent state.
- `paper-backup-*`: local snapshots or ad hoc backups.
- Dataset payloads and large pretrained weights under ignored directories.
- `visualizations/`, `fusion_wins_viz/`, `occlusion_samples/`: generated
  inspection outputs.
- `*.ckpt`, `*.pt`, `*.pth`, raw logs, and Python cache directories.
- Local secrets or account state such as `cookie`, `key`, `*.key`, and
  `*.settings.json`.

These files are useful during development, but they should not be treated as
source-of-truth project content.

## Root directory policy

The repo root should stay biased toward stable entrypoints:

- project metadata: `README.md`, `setup.py`, `environment.yml`
- core directories: `egoemg/`, `config/`, `scripts/`, `docs/`
- local-only research materials (`paper/`, `test_results/`) stay out of version
  control; they are regenerated by scripts or captured from local runs.

Avoid adding new one-off shell scripts, notes, backups, or generated outputs at
the root. If something is reusable, place it under `scripts/` or `docs/`. If it
is local-only, keep it ignored.

Generated visual inspection folders should live under `visualizations/`. If an
ad hoc visualization directory was created at the repo root, move it under
`visualizations/archives/<original-name>/` rather than leaving it top-level.

Keep local run-output directories under `local_artifacts/` when they do not need
a stable top-level entrypoint. The root `logs` symlink is the only log shortcut;
do not add duplicate symlinks such as `logs_temp`.

## Result hygiene

- `test_results/` is the curated, shareable surface for evaluation outcomes.
- Raw logs belong under `logs/`.
- Hydra `outputs/` dumps and similar run directories belong under
  `local_artifacts/`.
- Temporary checkpoint exports belong under `checkpoints/`.
- TensorBoard event files belong under `tensorboard/`.
- In `test_results/`, keep summary files such as `README.md`, `results.csv`,
  aggregate CSVs, and small Hydra config snapshots when they are needed for
  reproducibility.
- Do not track per-run checkpoints, event files, or copied training logs.

This keeps evaluation summaries readable without mixing them with bulky or
ephemeral artifacts.

## Triage commands

Use these commands when the workspace feels noisy:

```bash
git status --short
git ls-files --others --exclude-standard | sed -n '1,200p'
du -sh -- * .[^.]*
```

If `git status --short` mostly shows source, config, scripts, and docs, the
workspace is in a workable state. If it shows caches, checkpoints, raw logs,
visualization dumps, `paper/`, or `test_results/`, update `.gitignore` instead
of letting those files sit in the commit queue.
