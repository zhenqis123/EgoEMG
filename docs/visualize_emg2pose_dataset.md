# visualize_emg2pose_dataset.py: visualization pipeline and joint-angle semantics

This document explains the visualization path in
`scripts/legacy/visualize_emg2pose_dataset.py`
from HDF5 samples to mesh frames, and enumerates the meaning of each joint-angle
channel stored in the dataset.

## Data flow overview

1) Load session data
- `Emg2PoseSessionData(path)` opens the HDF5 and exposes the `egoemg/timeseries`
  structured dataset with fields `time`, `emg`, and `joint_angles`.
- Slicing the session (`session[start:stop]`) returns an array of records; the script
  extracts `emg` and `joint_angles` from that window.

2) Downsample to visualization rate
- The joint-angle time series is stored at the dataset sampling rate (2000 Hz). The
  script calls `downsample(joint_angles, native_fs=2000, target_fs=30)` to get a 30 Hz
  sequence for rendering.
- This is interpolation-based resampling, not a decimation.

3) Plotly mesh animation
- `get_plotly_animation_for_joint_angles` calls
  `generate_hand_mesh_frames_from_joint_angles`, which loops over frames and creates a
  `plotly.graph_objects.Mesh3d` per frame.
- Each frame is generated by converting joint angles into a skinned hand mesh using
  the UmeTrack hand model.

4) UmeTrack hand-model skinning
- `generate_hand_mesh_from_joint_angles` -> `skin_mesh_from_angles` -> `skin_vertices_np`
  -> `_skin_points` -> `_hand_skinning_transform` (UmeTrack) -> `so3_exp_map`.
- The joint angle values are treated as rotations about per-joint axes stored in the
  hand model (see `egoemg/UmeTrack/dataset/generic_hand_model.json`). For each
  joint, UmeTrack computes a local transform from axis-angle and chains the transforms
  along each finger.

## Joint-angle array shape and unit

- In the dataset, `joint_angles` is stored as a `(T, 20)` array in the HDF5 record.
- The visualization pipeline uses these 20 angles directly (no wrist DoF is included
  in the dataset channels).
- Angles are interpreted as **radians** in the visualization path and the UmeTrack
  forward-kinematics utilities.

## Joint-angle channel definitions (index -> meaning)

The 20 channels correspond to 5 fingers x 4 DoF per finger. The ordering and naming
are defined in `egoemg/constants.py`.

## Notes about IK failures

- The visualization path does not mask IK failures when rendering the GT mesh.
  It always renders all frames in the selected window.
- IK failures are detectable as all-zero joint angles (see `get_ik_failures_mask`),
  and the script generates a diagnostic plot with `ik_failure_plot`, but it does not
  filter or skip those frames.
