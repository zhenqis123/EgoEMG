## Resolution (2026-06-08)

The reproduction was **closed on the first eval against the new memmap**. The
filter-pipeline investigation was a red herring; the actual root cause was
**normalization**: the stored `egoemg` norm stats in
`assets/per_dataset_norm_stats.json` (mean=0.029, std=94.74) were computed on
**raw** EMG, but the historical checkpoint was trained on **filtered** EMG
whose post-layout std is ~8.7. Dividing the filtered signal by 11× the
correct std compressed the model input into noise and pushed test_mae from
0.240 to 0.297.

### Evidence

Direct stats from the new memmap (now consolidated into `data/EgoEMG_memmap`):

| Source | mean | std |
|---|---|---|
| Stored `egoemg` key in `per_dataset_norm_stats.json` | +0.029 | **94.74** |
| `emg_left_filtered` (8ch raw) | -0.000 | 0.92 |
| `emg_right_filtered` (8ch raw) | -0.000 | 5.96 |
| Post-layout pooled (8ch→16ch sparse-place, both hands) | +0.0008 | **8.66** |

The ~11× std mismatch is what drove the 0.057 MAE gap.

### Closed-loop results

| Eval | test_mae | Notes |
|---|---|---|
| Old ckpt on memmap + `filtered` + stored `egoemg` norm | 0.2970 | broken |
| Old ckpt on memmap + `filtered` + correct `egoemg__filtered` norm | **0.2424** | matches historical 0.2401 |
| Old ckpt on memmap + `filtered` + per-hand norm | 0.2436 | pooled norm slightly better |

The 0.0024 residual is within sampling/run-to-run noise (4M/hand sampled out
of 33M frames is statistically tight; not from filter-pipeline
mismatch). The historical `emg_*_filtered` columns in the new memmap are
genuinely compatible with the historical checkpoint.

### Fix landed

1. **`assets/per_dataset_norm_stats.json`** restructured to field-aware
   keys `<dataset>__<emg_field>`:
   - `egoemg__filtered` (pooled, both hands, post-layout): mean=0.0008, std=8.66
   - `egoemg__filtered_left` and `egoemg__filtered_right` (per-hand, for
     experiments that want separate normalization)
   - `egoemg__raw`, `egoemg__filtered_paper`,
     `egoemg__filtered_aligned` (placeholders to be filled by the new
     computation script)
   - Legacy `egoemg` key kept as a back-compat alias to `egoemg__raw`.

2. **`emg2pose/datasets/egoemg_memmap_dataset.py::_load_norm_stats`** now
   resolves `<dataset>__<emg_field>` first, falls back to legacy
   `<dataset>`, and emits a WARNING when the resolved std is ≥20 on a
   non-raw field (the tell-tale sign of the original bug).

3. **`scripts/data/compute_per_dataset_norm_stats.py`** is the new canonical
   way to populate the JSON. It samples from a memmap directory, applies
   the same `_convert_to_emg2pose_layout` transform the dataset does, and
   writes both pooled and per-hand keys. To populate the remaining
   placeholders:

   ```bash
   python scripts/data/compute_per_dataset_norm_stats.py \
     --memmap-dir data/EgoEMG_memmap \
     --emg-fields raw filtered filtered_paper filtered_aligned \
     --dataset-name egoemg \
     --layout emg2pose_interpolate16 \
     --channel-indices 10 12 0 1 2 4 5 6 \
     --n-samples 4000000 \
     --output assets/per_dataset_norm_stats.json
   ```

### Why the "old files are missing" hypothesis was wrong

The new `emg_{left,right}_filtered` files are
numerically equivalent to the historical ones — the checkpoint
evaluates correctly once norm is right. The "filtered file is missing"
line of investigation was chased because the norm-bug symptom (0.297 MAE
across multiple filter variants) looked like data drift. The giveaway
was the **std=94.74**: it's a number that only makes sense for raw EMG,
and applying it to filtered EMG is mathematically equivalent to shrinking
the input by 11×, which is exactly the failure mode the model exhibited.
